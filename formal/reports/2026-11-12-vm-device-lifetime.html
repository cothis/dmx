VM lifetime: four lifecycle findings repaired

2026-11-12 · L1, L2, L4, G10 · 13 findings remain open.

Before repair a device stop returned while its queue callback was blocked. Forcing a stale release against a successor VM makes that real guest fail to boot when the alive fence is removed.

Reproduction and repair

  • L1: synchronize terminal device queues, weak Machine captures, guard release and interrupts under the mapping lock. The original queue regression fails; restored code passes.
  • L2: clean failed partial initialization and wait for failed-start teardown. Independent mutations fail their corresponding entitled VM tests.
  • L4: reject completions from detached/cancelled controllers. A delayed old swap reply cannot set the successor flag.
  • G10: construct the immutable share root before publishing the server. Existing FUSE tests pass; no separate race reproduction is claimed.

Verification and limits

120 unit tests · 4 entitled VM tests · 23 selftest checks · 63 daemon checks · four 2 GiB release/restart cycles.

Selftest footprint 98 → 97 MiB, one sample each; this does not establish a memory saving. The model checks 10 reachable states: one split device callback, one independent external callback, two VM generations. Both independent defense mutations, old behavior and the reachability invariant fail as expected. No liveness, natural race-rate or whole-program claim. Trust base: Swift/Rust toolchains, Hypervisor.framework, pinned guest, TLC and manual code/model correspondence.
