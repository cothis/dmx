F1 · high severity · fixed

Framed socket I/O can cross into a different connection after close

FrameConnection serialized writes and made close idempotent, but its read/write loops still used the released descriptor integer. A subsequent socket can reuse that number. A stale writer then transmits old payload to the new socket, and a stale reader consumes the new socket's bytes. AgentClient replacement and concurrent exec stdin/output make delayed operations relevant production callers; the reproduction establishes the code path, not its field frequency.

NoForeignIO == ~foreignIO — A frame never reads from or writes to an unrelated socket after descriptor reuse.

Fix

Check closed and duplicate the socket under closeLock; hold a private CLOEXEC descriptor through the entire read or write frame, releasing it with defer. Close also shuts the socket down, waking operations on duplicates. Public signatures and wire framing are unchanged.

Core of the change (the complete source diff also routes both frame paths through this helper):

private func withOpenFD<T>(_ body: (Int32) throws -> T) throws -> T {
    closeLock.lock()
    let copy = closed ? -1 : fcntl(fd, F_DUPFD_CLOEXEC, 0)
    let failure = closed ? "connection closed" : String(cString: strerror(errno))
    closeLock.unlock()
    guard copy >= 0 else { throw DMXError("\(peer)_disconnected", "\(peer): \(failure)") }
    defer { Darwin.close(copy) }
    return try body(copy)
}
// writeFrame and readFrame execute through withOpenFD;
// close performs shutdown(fd, SHUT_RDWR) before releasing the original.

Scope and assumptions

Modeled

  • One FrameConnection, two frame operations, close/abort and descriptor-number reuse.
  • Frame acquisition and close use separate locked actions; each syscall is a separate transfer action.

Abstracted

  • Payload/framing contents, descriptor integers, time and kernel scheduling.
  • Private duplicate lifetime is represented by a lease; successful duplication is assumed, because failure rejects the operation safely.
  • Each syscall returns in one step; blocked-I/O liveness is not proved.
  • A real EOF/error can return earlier; permitting both finite transfer steps overapproximates I/O for safety and does not verify error handling.

Out of scope

  • Raw FrameConnection.fd consumers (splice/relay, Docker HTTP).
  • Guest vsock flow control, VM destruction, process crashes, and hostile external close of an owned descriptor.
  • Unbounded theorem proving, OS implementation correctness and production failure frequency.

Assumptions

  • NSLock serializes duplicate acquisition and close.
  • F_DUPFD_CLOEXEC retains the same open file description while the original integer may be reused.
  • Only the frame's defer releases its private duplicate.
  • The code/model correspondence was reviewed manually, not proved as Swift refinement.
