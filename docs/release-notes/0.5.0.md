## Changes since 0.4.8

New:

- `dmx import` copies images, volumes with their data, bridge networks and containers (created,
  not started) from Docker Desktop, OrbStack, Colima, Rancher Desktop or any Docker socket.
  `--project` limits it to one Compose project and `--dry-run` shows what would happen. Existing
  names are never overwritten, and an interrupted import is recognised and cleaned up the next
  time. MCP clients get it as `dmx_import`.
- Local names: after `dmx names setup`, `https://<container>.dmx.local` and
  `<service>.<project>.dmx.local` reach running containers from the Mac's browsers with no
  warning. The CA can sign names under `dmx.local` only, and `dmx names remove` takes it, and
  the resolver file, out of macOS again.
- `dmx bench` measures idle memory and CPU, warm `docker run` time, and how fast memory a
  container frees returns to the Mac. It can compare dmx with other engines (`--engine`).
- Guest crash recovery: a guest kernel panic or a VMM fault no longer leaves the VM reported
  as running at high CPU. The daemon keeps the console tail in `~/.dmx/logs/guest-crash.log`.
  If containers were running, it boots a new VM, and containers come back by their restart
  policies. It stops after ten crashes in a row.

Fixed (several were in 0.4.8):

- Ctrl-C on `dmx sandbox exec`, or an MCP cancel, now kills the command in the sandbox.
- A memory setting that is not whole 128 MB blocks above boot RAM (`dmx config set memory
  3000M`) stopped the daemon at every boot.
- A sandbox whose network rules could not be set again after a restart kept running without
  them. Sandboxes now also turn IPv6 off.
- Docker starts at boot by dockerd's own restart rule. `docker stop` keeps only
  `unless-stopped` containers down, and an `on-failure` container that was running at a crash
  comes back.
- Limits keep a LAN sender or a runaway client from using up the daemon's descriptors:
  - each forward takes 1024 TCP connections and 512 UDP peers;
  - all forwards together take 4096 TCP connections and 2048 UDP peers;
  - docker.sock takes 1024 connections and the control socket 256;
  - all shares together take 6144 open files.
- A guest that ignores the host's limits can no longer crash the daemon or grow its memory
  without bound.
- Hardening against bad input:
  - a hand-edited config.json is checked before it reaches the kernel command line;
  - `dmx_config_set` (MCP) may change only cpus, memory and idle_timeout;
  - downloads are bounded in size before their hash is checked.
- Every failure has a JSON envelope under `--json` and a hint naming the next command.
- Outbound connections from containers notice a far end that vanished (sleep, Wi-Fi or VPN
  change) instead of holding their sockets for good. Freed memory goes back to macOS sooner
  (libmalloc's space-efficient mode), and vCPU threads stay off the efficiency cores.
- The guest is rebuilt from re-pinned inputs (Docker 29.9.3, runc 1.4.4). The kernel, FEX and
  qemu-x86_64 are byte-identical to 0.4.8's.

This release includes a rebuilt guest. Updating the app keeps a running VM and its containers;
stop and start the engine to use the new guest.
