## Changes since 0.3.3

This release fixes host/guest boundary defects and invalid-input crashes found in the final
pre-announcement review. Upgrading is recommended, especially when using host directory shares.

- **Shared-file operations keep their descriptors until they finish.** A guest closing a handle
  while another request used it could make that request operate on a descriptor reused by a
  different host file. Each file operation now holds its own duplicate, and directory streams
  stay open until the last reader finishes. Regression tests cover release during file I/O and
  concurrent directory reads and closes.
- **Read-only shares preserve host file permissions.** An open request asking to clear set-ID
  bits is refused with EROFS on a read-only share; it previously changed the host file's mode.
- **Malformed virtqueues no longer crash the host through address arithmetic.** The complete
  descriptor table and ring ranges are checked before adding offsets, together with queue sizes,
  available indices and completion lengths. Out-of-range guest addresses are rejected.
- **Malformed sandbox network entries return errors.** Empty hosts, `/`, and malformed CIDRs
  no longer index an empty array or silently accept a missing prefix length.
- **Oversized memory, disk and TTL values return errors.** Sizes that do not fit signed host
  integers are rejected before use. MCP TTL values such as `1e100` no longer terminate the MCP
  server, and Docker JSON integer conversions reject nonrepresentable values.
- **x86 signal return and concurrent code decoding are corrected.** FEX now restores its syscall
  marker even when a signal handler leaves the instruction pointer unchanged, preventing later
  signals from overwriting live stack data. Its decoder reads aligned code words once per
  instruction so an atomic method-entry rewrite cannot mix old opcode bytes with new operands.
  The original guest intermittently crashed during Java compilation; the final guest passed
  100 repeated amd64 Java compilation/JIT workloads. A signal-frame regression runs under both
  FEX and QEMU. See the [diagnosis and bounded evidence](https://github.com/cothis/dmx/blob/v0.3.4/docs/fex-java-2026-10-27.md).
- **Documentation now matches the implementation.** IPv6 support and its remaining external
  network acceptance boundary are stated correctly, update help describes the daemon's natural
  idle exit, release instructions include FEX and the full acceptance suites, and the handoff
  distinguishes published releases from review work.

Final qualification passed 59 unit tests, 23 VM selftests, 57 daemon checks, 33 MCP checks,
49 x86 checks, 69 Docker checks, 44 sandbox checks, all 24 digest-pinned image cases across arm64,
amd64 and 386, and the 100-run Java gate. The preceding host-boundary review also passed 12
memory-pressure/disk-recovery rounds. With the final guest, idle VM footprint was 97 MiB and
roughly 1 GiB returned in 105 ms after the guest freed it. These are bounded local measurements, not a new
comparison against other engines or a guarantee for every JVM and workload.

The updated guest includes `fex-2610-dmx9`. Existing installations download it for the next boot;
updating the host binary leaves a running VM alone, and the persistent data disk is retained.
Corporate TLS-inspection networks and external IPv6 still need acceptance in environments that
provide them.
