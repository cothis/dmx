## Changes since 0.3.1

Four things the 0.3.0 and 0.3.1 releases showed were missing.

- **Updating no longer downloads the Linux guest again when it has not changed.** A release
  usually ships the boot files of the one before it — 0.3.0 and 0.3.1 have the same kernel,
  initramfs and Docker image, and their guest archives differ only in the version named inside —
  so dmx now compares the sha256 of each boot file (both the binary's pin and the installed
  guest's receipt carry them) and keeps what is on disk. Updating from 0.3.1 moves 1.8 MB instead
  of 64 MB.
- **`dmx update` checks who signed the download.** A sha256 published next to the archive proves
  the transfer, not the publisher. So when the dmx being replaced is signed with a Developer ID,
  the downloaded binary has to carry the same team's signature and pass `codesign --verify`; an
  unsigned dmx (built from source) says it skipped the check rather than claiming a match.
- **Release notes are part of the repository.** `docs/release-notes/<version>.md` holds the
  "Changes since" section and `make release` folds it into NOTES.md before writing SHA256SUMS,
  which three releases had done by hand. Packaging a version without notes is refused.
- **`dmx doctor` names the daemon.** When the daemon answering is from another dmx — which is what
  happens between an update and the next `dmx stop` — doctor says both versions and what to do.
