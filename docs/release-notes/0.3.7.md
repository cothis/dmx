## Changes since 0.3.6

A small fix for setting up the docker CLI, and documentation for using dmx at work.

- **`dmx install` and `dmx tools install` replace a `docker` link that points at nothing.** They
  never replace what dmx did not put on your PATH, and they used to treat every existing link
  that way. A link left behind by a deleted `DMX_HOME` or an uninstalled engine was therefore
  kept. On a Mac where it was the only `docker`, installing dmx's CLI left no working `docker`
  at all. Such a link is now replaced, and `dmx tools ls` calls it broken. Links that still lead
  somewhere, and plain files, are left alone as before.
- **README states how dmx is signed, and how to check it.** "Using dmx at work" now names the
  Developer ID (team `V4YA23448U`), the hardened runtime and the single hypervisor
  entitlement, gives the two `codesign` commands that confirm signature and notarization,
  and explains why `spctl` answers "not an app" for a command-line tool.
- **The benchmark table was re-checked on 0.3.6.** dmx alone, with the same protocol: idle
  222 MB, 0.37 % of one core, 2 GiB returned in 2 s, all within the 0.3.0 ranges.

Qualification passed 60 unit tests, 23 VM selftests (idle 95 MiB), 58 daemon checks, 33 MCP
checks, 53 x86 checks, 69 Docker checks, 44 sandbox checks, all 24 digest-pinned image cases and
the 100-run Java gate. The guest is unchanged from 0.3.6, so updating does not download it again.
