## Changes since 0.4.7

- Drain VM device work before destroying Hypervisor resources, fence stale callbacks and clean up failed initialization and starts. A stuck host file operation now ends the engine within a bounded deadline instead of freeing memory still in use.
- Keep exec cancellation responsive with negotiated stdin byte credit, bounded guest queues and reliable child/PTY cleanup. A previous guest retained after a failed upgrade supports small stdin; input above 4 KiB fails with `guest_upgrade_required` and the command needed to fetch the updated guest.
- Give shutdown and clock work independent control connections. Clock samples begin after connection setup; connection EOF releases waiting input writers.
- Recover from host disk exhaustion without aborting the guest filesystem. Flush unpacked Docker/emulator data before publishing its durable marker.
- Bound UDP, socket-accept and daemon-start retry paths. Read fragmented UDP replies without inventing empty datagrams; retire Docker listing retries and connections when dockerd stops. Half-closed TCP flows expire after 30 minutes without progress, with valid ACKs renewing the deadline.

This release includes a rebuilt guest. Updating the app preserves a running VM and its containers; stop and start the engine to use the new guest. An offline upgrade can boot the previous guest, with the stdin limit described above.
