## Changes since 0.3.0

- **`dmx update`.** It resolves the newest release, downloads the binary with the sha256 published
  beside it, runs what it unpacked to check the version, and replaces the file it is running from.
  `dmx update --check` only reports whether a newer release exists; `--version` installs a named
  one (a release mirror has no "latest" page, so there it is required). A build from source and a
  directory it cannot write are refused with a hint rather than overwritten.
- **A notice when the daemon is from another dmx.** The daemon that is already running keeps
  serving the version it was started with, so after an update a command could quietly run the old
  engine. Every command now says so, and `dmx update` reports the handover: a VM that is running is
  left alone (`dmx stop` powers it off and the daemon exits a few seconds later), an idle daemon is
  asked to quit so the next command runs the new version.
- The guest is the one 0.3.0 shipped. Its archive here differs only in the version its
  THIRD_PARTY.md names, so a 0.3.0 user who updates downloads it once more.
- `make daemontest` covers the update: the plan, the refusal to overwrite a source build, a copy of
  the binary really updated to a published release, and the notice. Its DNS check also no longer
  depends on whether the Mac's own `.local` name resolves to `::1`.
