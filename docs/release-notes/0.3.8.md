## Changes since 0.3.7

A fix for `dmx install`, which could fail while launchd was starting the daemon it waited for.

- **`dmx install` waits for launchd instead of checking once.** It replaces the launchd agent
  by unloading the old job and loading the new one. Unloading returns while the old daemon is
  still exiting, which takes over a second when it powers a VM off. Loading the job in that
  window either failed with `Bootstrap failed: 5: Input/output error` or loaded a job that was not
  active yet. install then connected exactly once and gave up with "launchd did not start the
  daemon", although launchd started it milliseconds later. On a Mac with an endpoint security
  agent, the whole install took 58 ms, and the daemon came up about 20 ms after install had given up. The
  Docker context was then never created. install now waits until launchd has let go of the old
  job and its process, retries the load for a few seconds, and keeps connecting for up to 10 s.
  If launchd still does not answer, the error says why the connection failed and what state
  launchd reports for the job. With the VM running before each install, 0.3.7 succeeded 5 times
  out of 10 and this release 10 out of 10.

If `dmx install` failed for you on 0.3.7, run it again after updating: it finishes the docker
context it could not create.
