## Changes since 0.3.10

This patch fixes socket lifetime during disconnects and reports the current guest release
when an update keeps the same boot files.

- **Keep framed I/O on its own socket when a connection closes.** A delayed read or write
  could use the old file descriptor number after another socket had reused it, consuming or
  sending bytes on the unrelated connection. Frames now acquire an owned descriptor under
  the close lock and retain it through header, body and short transfers. Closing also shuts
  down pending I/O. Three real-socket regression tests fail before the fix and pass after it.
- **Refresh the guest release receipt even when no download is needed.** Patch releases
  often ship identical boot files. Those files are still kept, but `dmx guest` and
  `dmx doctor` now report the new release tag after the next boot instead of an older one.

The socket fix was checked with a focused TLA+ model: one connection, two frame operations,
two system calls each, and descriptor reuse. Its two safety properties hold in 134 reachable
states; removing the fix produces a counterexample again. This is bounded model checking,
not a proof of the whole program. Models, code correspondence, real reproductions and logs
are in `formal/`.

An update keeps a running VM and its old daemon. When ready to switch the daemon too,
run `dmx stop`; the next command starts 0.3.11 and refreshes the guest receipt.

Qualification passed 66 unit tests, 23 VM selftests (idle 96 MiB), 58 daemon checks, 33 MCP
checks, 53 x86 checks, 69 Docker checks, 44 sandbox checks, all 24 digest-pinned image cases and
the 100-run Java gate. The guest boot files are byte-identical to 0.3.10.
