## Changes since 0.4.3

- FEX now raises x86 integer divide errors correctly. amd64 .NET and Java programs get their divide-by-zero exceptions, with the interrupted registers, flags and floating-point state intact. Inherited ignored host signals no longer swallow synchronous fatal faults.
- .NET can update its JIT code through a new writable alias without running an old translation. Signal handlers can edit their return context and mask; temporary masks in poll/select/epoll waits work on amd64 and 386. Repeated jumps out of handlers reclaim abandoned host frames, and vfork no longer waits for a descendant that outlives its child.
- Signals waiting for an exact guest state retain their ordinary realtime order and payload. REP CMPS no longer exposes temporary flag values to a handler.
- A blocked local-network startup probe is retried after three seconds before logging the block. This avoids a transient first-probe report on this Mac; it is not a promise that every signed update retains macOS permission.

The final emulator is `a75324c3ee1e`. Managed-runtime checks passed three times each: .NET's exception workload returned `320000`, Java caught `400000` divide-by-zero exceptions and returned the expected MIN_VALUE/-1 results. Eight paired rounds against dmx12 on a quiet Mac measured median differences of -0.03% (tight loop), -0.02% (compile storm), +0.04% (Python loop), and +0.49% (Python start). Fresh-boot footprint medians were both 96.5 MiB.

Known local-network issue: in a signed 0.4.3-to-0.4.4 update on this Mac, permission changed from `allowed` to `blocked`, and LAN TCP was blocked too. If LAN access stops after updating, check the macOS prompt or System Settings > Privacy & Security > Local Network and allow dmx. Public internet access still works. The three-second probe retry does not establish permission continuity.

Known limits: some rare FEX signal, stack-switching and writable-alias combinations remain; see the [recorded compatibility limits](https://github.com/cothis/dmx/blob/main/docs/PLAN.md#dmx13-signal-contexts-writable-code-aliases-and-divide-errors-2026-11-05-candidate). The AAAA fix from 0.4.2 has not yet run on the network that originally showed the failure. A newly signed public update still needs its own local-network permission check.

The guest changes in this release: it carries the new emulator, so updating downloads it once.
