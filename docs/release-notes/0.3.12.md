## Changes since 0.3.11

This patch fixes RPC reply alignment under file-descriptor pressure and strengthens the
formal models and regression tests used to check socket lifetime.

- **Keep one descriptor lease for the complete RPC exchange.** v0.3.11 acquired separate
  leases for request and response frames. If the second dup failed after sending, a later
  call could receive the previous reply. Acquisition now happens before transmission, reply
  IDs are checked, and uncertain transport/protocol failures retire the connection. Future
  calls can reconnect; a possibly applied request is never automatically replayed.
- **End failed server replies.** A daemon whose reply lease failed could keep waiting for
  the next request while its client waited for this response. Serving-side sends now close
  on failure, including partial writes. Daemon application errors retain their original
  code, message and hint.
- **Refresh equal-archive receipts.** A changed release tag now updates the guest receipt
  even when the archive hash and boot files are identical, without downloading again.
- **Repair verification blind spots.** Descriptor bindings and queued reply IDs determine
  observations; fix switches cannot precompute success. Independent guard, ownership,
  atomicity, correlation, retirement and replay mutations fail the frozen properties.
  Wakeup is asserted before peer teardown; destructive FD reuse is isolated in children.
  `make formaltest` builds current Core, runs both models and the real-syscall probes.

Two bounded TLA+ safety models pass: 134 reachable FD states and 26 RPC states. Thirteen
additional mutation/reachability checks fail on their required invariants. These are
scoped model checks, not whole-program proofs. The original evidence, why the first check
missed the bugs, actual Opus 5.5 reviews and installed skill improvements are preserved
under `formal/` and `docs/formal-verification-miss-2026-10-29.md`.

An update keeps a running VM and its old daemon. Run `dmx stop` when ready to switch;
the next command starts 0.3.12. The guest boot files are unchanged from 0.3.11.

Qualification passed 76 unit tests, 23 VM selftests (idle 99 MiB), 58 daemon checks, 33 MCP
checks, 53 x86 checks, 69 Docker checks, 44 sandbox checks, 24 pinned image cases and the
100-run Java gate. The full matrix preceded the final two error-path fixes; those fixes
were rechecked with unit, VM selftest, daemon, MCP, syscall fault and formal guards.
A deterministic replay demonstrated a legal two-snapshot false rejection in a daemon
memory test; it now uses the qualifying sample with the same limits/deadline. The first
57/58 run is retained; its exact accepted sample was not recorded, so attributing that
particular failure to the race remains an inference. The corrected daemon/MCP suites pass.
