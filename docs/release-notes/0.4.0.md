## Changes since 0.3.12

- Launch **dmx** from Applications or the app launcher for a native menu bar status item,
  engine/menu memory, container list and Start/Stop, logs, errors and Retry. Quit stops
  the engine and app together. Normal idle shutdown closes the app too. No GUI login item
  or background status polling; terminal use remains independent.
- One installer installs `~/Applications/dmx.app`, its CLI link in `~/.local/bin`, and pinned
  Docker CLI/Compose/Buildx tools. Both executables are Developer ID signed with hardened
  runtime; the app is notarized and carries a stapled ticket.
- `dmx update` updates an app installation as a complete signed bundle, preserving a running
  VM and its containers. Reopen the app to use the new menu. The legacy standalone CLI stays
  in the archive for older updaters. To add the app to a 0.3.12 or earlier installation, run
  this release's installer once; those old updaters only know how to replace their CLI.
- Menu Docker requests refuse to boot an idle VM and preserve the independent CLI socket's
  keepalive. Idempotent container Start/Stop accepts Docker's 304 response. Operation failures
  do not retain the app after normal engine shutdown; unexpected engine failures remain visible.
- First-run Quit cancels guest/tool downloads. Once a VM has started its first disk format,
  shutdown waits for the guest agent (up to 120 seconds) before graceful poweroff, preserving
  the disk. Menu control and Docker requests have deadlines.

Qualification and measured menu cost are recorded in `docs/menu-app.md` and the release
measurement file. API/VM tests and GUI callback evidence are identified separately.

Qualification passed: unit runner92 (two opt-in suites run separately), VM selftest23, daemon58,
MCP33, x8653, Docker69, sandbox44, images24 and Java100 repetitions; menu lifecycle25, typed
MenuEngine VM and signed whole-app update with VM/container/named-volume preservation. Actual
Opus5.5 final code review approved. A real179-second first download and bad-context startup
both converged to normal idle UI exit. Direct Start/Stop/Quit GUI clicks remain a documented
manual acceptance item; API/VM tests are not presented as click evidence.
