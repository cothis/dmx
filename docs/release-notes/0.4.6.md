## Changes since 0.4.5

- Fixed `AF_INET6`-only lookups on networks that never answer AAAA. An AAAA query with no A query beside it had nothing to end its wait, so a name with an address failed with `Temporary failure in name resolution` after 5 to 10 s. The gateway now looks up the name's A record itself, and once it finds an address waits 1 s for a late AAAA, then answers that the name has no IPv6 address. A name with no address at all still fails after 5 s, which the client may retry.

Measured with a multicast record that answers A and leaves AAAA silent, from a glibc container: `AF_INET6` went from `Temporary failure` after 5.06 and 10.03 s to no address in 1.04 and 1.01 s; `AF_UNSPEC` stayed at 0.31 s, and a name with both records at about 0.01 s. The two new checks fail on 0.4.5. Memory is unchanged: host footprint with one container 310 MB against 318 MB on 0.4.5.

Confirmed where it failed (corrected 2026-11-05): the maintainer reports that 0.4.6 works on the network that showed the failure. An earlier version of this note said the fix had not yet run there.

Known limit: on that network, each lookup of a name with an unanswered AAAA still takes about 0.3 s, by design.

The guest's boot files do not change, so updating from 0.4.4 or 0.4.5 downloads nothing more.
