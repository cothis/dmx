## Changes since 0.3.9

Tools that look for Docker Desktop's socket instead of reading the docker context now find dmx.

- **`dmx install` links `~/.docker/run/docker.sock` to `~/.dmx/docker.sock`.** The docker CLI
  already reached dmx through the `dmx` docker context. Some SDKs, IDE plugins and Testcontainers'
  fallbacks skip the context, though, and only try Docker Desktop's paths (`/var/run/docker.sock`,
  `~/.docker/run/docker.sock`, `~/.docker/desktop/docker.sock`). They then failed with "no such
  file or directory". The link is in your home directory, so it needs no sudo. A socket that
  Docker Desktop serves there is left alone, and so is a link to another engine's socket that
  still exists. A dangling link or a dead socket left by an engine you removed is replaced.
  `dmx uninstall` removes the link only if it is dmx's.
- `/var/run/docker.sock` needs root, and dmx does not ask for a password. For a tool that tries
  only that path, set `DOCKER_HOST=unix://$HOME/.dmx/docker.sock` where it runs. Testcontainers
  also reads `docker.host` from `~/.testcontainers.properties`.

After updating, run `dmx install` once to create the link.
