## Changes since 0.3.4

This release fixes how the x86 emulator (FEX-Emu) handles code that another thread rewrites,
which JIT runtimes such as HotSpot do all the time. Upgrading is recommended for amd64 images
that run Java or other JIT-compiled code.

- **The cause of 0.3.3's intermittent Java crash is now confirmed, and 0.3.4 had already fixed it.**
  Every crash report matches FEX decoding HotSpot's atomically patched method entry with
  the opcode from the old version and the operand from the new one. The fault addresses
  and registers recompute exactly. A new regression program reproduces it: the old emulator failed 18 of 20
  runs, while 0.3.4's guest, this guest and QEMU passed all of them.
- **Rewritten code no longer keeps running in its old translation.** FEX write-protected a page
  only after translating code on it, so a write landing in between went unnoticed. The block
  kept running the old bytes after the new ones were published, even after the writer and
  the caller had synchronized as x86 requires. A second regression program failed every run on
  0.3.4's guest and passes now. FEX now checks the code it decoded once the page is protected,
  and translates it again if it changed. Pages already known to be protected are not
  protected again, so a burst of 262,144 JIT-style compiles takes 248–259 ms, against 268–270
  ms with 0.3.4's guest (318–324 ms before that optimization).
- **x86test runs both programs** three times under FEX and under QEMU, beside the signal-frame
  check from 0.3.4.

Qualification on the new guest passed 59 unit tests, 23 VM selftests, 57 daemon checks, 33 MCP
checks, 53 x86 checks, 69 Docker checks, 44 sandbox checks, all 24 digest-pinned image cases
across arm64, amd64 and 386, and the 100-run Java gate. Idle VM footprint and memory return were
unchanged. See the [diagnosis](https://github.com/cothis/dmx/blob/v0.3.5/docs/fex-java-2026-10-27.md) and
[measurements](https://github.com/cothis/dmx/blob/v0.3.5/docs/measurements/2026-10-27-fex-code-patching.json).
These are bounded local measurements, not a guarantee for every JIT and workload.

The updated guest includes `fex-2610-dmx11`. Existing installations download it for the next
boot; updating the host binary leaves a running VM alone, and the persistent data disk is
retained.
