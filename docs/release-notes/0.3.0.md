## Changes since 0.2.2

x86 emulation is the headline: amd64 images run through FEX-Emu with the Apple CPU's hardware TSO
memory model instead of QEMU user mode, and 32-bit (`linux/386`) images run as well.

- **FEX-Emu as the default x86 emulator.** `docker run --platform linux/amd64` now goes through
  FEX-2610, built as a static musl binary from pinned sources, instead of qemu-x86_64. The guest
  kernel carries Asahi Linux's `PR_SET_MEM_MODEL` patches, so FEX asks the kernel for the Apple
  CPU's TSO memory model and translated x86 code needs no memory barriers. CPU-bound x86 code is
  2.5 to 9 times faster: a Python loop 1663 to 190 ms, a 100 MB SHA-256 1.3 times native instead
  of 3.3, the PostgreSQL image workload 5.2 to 2.8 s. `dmx config set x86_emulator qemu` switches
  back to QEMU (amd64 only).
- **32-bit x86 images.** `linux/386` images run under FEX. The image matrix passes 24 of 24
  across arm64, amd64 and 386 (six of its nine images publish a 386 manifest), Redis's jemalloc
  and PostgreSQL included.
- **Node starts 2.5 times faster under emulation.** A translated block holds 150 x86 instructions
  rather than FEX's default 5000, which was compiling superblocks out of code that runs once:
  `node -e 0` takes 246 ms instead of 650 (QEMU 370), and the memory FEX held after x86 work fell
  by about 60 MB.
- **Less CPU at idle.** An idle guest is trimmed once per idle spell instead of every time its
  page cache grows back, which took the idle process from 1.4 % to about 0.5 % of one core.
- **Security of x86 emulation.** binfmt_misc runs the emulator with a setuid x86 program's
  credentials, as Docker Desktop does, so dmx's FEX ignores the caller's configuration for such an
  exec (the `FEX_*` variables and `$HOME/.fex-emu`) instead of letting an unprivileged caller
  choose the code it runs.
- **Correctness fixes in the emulator.** FEX reserves the address space above 2^47 even where
  `/proc` is not in the program's root, so allocators like jemalloc and mimalloc cannot be handed
  addresses they do not fit; without that, BuildKit's emulator probe ran with the wrong layout.

done, and the measurements behind these numbers are in
