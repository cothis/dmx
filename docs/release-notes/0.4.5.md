## Changes since 0.4.4

- Fixed name lookups failing for S3 and other names with long answers. An S3 bucket's name, as boto3 uses it, is a CNAME and eight addresses; dmx did not compress names in DNS replies, so the reply exceeded 512 bytes and came back truncated. glibc then retried both address families over TCP, and that went to the Mac's first DNS server instead of macOS's resolver, so `getaddrinfo` could fail while an IPv4-only lookup worked. Replies now compress names (that S3 reply went from a truncated 512 bytes to a whole 211), and the gateway answers DNS over TCP with macOS's resolver, as it does over UDP.
- Names only macOS knows (a VPN's split DNS, `.local`) and the rule for networks that never answer AAAA now hold for answers too large for UDP as well.
- DNS over TCP to the gateway answers "not implemented" for what macOS's resolver path does not take: zone transfers, the root name, several questions in one message. A client that needs those can name a server directly.

Real boto3 calls reach S3 from glibc and musl containers, on the default bridge and a user network, on arm64 and on amd64 under FEX. Ten of the eleven new Docker checks fail on 0.4.3. Memory is unchanged: host footprint with one container averaged 295.25 MB against 295.75 MB in alternating rounds on the same guest.

Confirmed where it failed (corrected 2026-11-05): on the network that showed the failure, S3 `AF_UNSPEC` lookups went from 10/10 failures on 0.4.4 to 25/25 successes on 0.4.5, and five other hosts passed 110/110. An earlier version of this note said the fix had not yet run there.

Known limits: on a network that never answers AAAA, an `AF_INET6`-only lookup can still fail after 5 to 10 s. Past a socket pair's 8 KB buffer (about 250 pipelined queries, or one query over 8 KB) a TCP query waits for the guest's retransmit: slower, never wrong.

The guest's boot files do not change, so updating downloads nothing more.

## Qualification

On the release version, with the previous guest pin until packaging: unit 105 and bounded formal checks, selftest 23, daemon 61, MCP 33, x86 77, Docker 80, sandbox 44, image matrix 24, Java JIT 100/100, menu, app installation 14, storage 64, and local network 12 (real LAN compared, allowed). Boot selftest host footprint: 94 MB. An independent model review found one defect, which is fixed: a connection left with part of a query stayed open. Its test fails without the fix.
