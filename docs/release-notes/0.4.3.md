## Changes since 0.4.2

- `linux/amd64` Go programs no longer crash under FEX. Go's asynchronous preemption needs an exact register state, and FEX showed its signal handler a half-done
  instruction or stale registers. `gosu`, in many official images, failed 14-27% of runs on 0.4.2 (`postgres` start-up was the visible case) and none of 2000 now.
  Go 1.27 failed at `go version` under 0.4.2; `go build -a std` now works, and a program with call-free loops and collections ran 8 minutes. x86 emulation costs 1-5% more for this
  (measured: Python loop +4.6%, a tight loop +3.9%, compile storm +1.2%, Python start unchanged).
- Other FEX fixes found on the way: busybox's `timeout` in amd64 images always ran to its limit and killed the command; a process exiting while a timer fired could crash;
  a guest fault could crash the emulator while reading the signal frame; a thread could sleep forever with signals masked.
- Programs can allocate more than the memory plugged so far. A 2 GiB mapping failed even natively in a VM that could reach 8 GiB, because the kernel's default heuristic compared it with
  `MemTotal`. `vm.overcommit_memory=1`, as in LinuxKit: running really out of memory now ends in the OOM killer rather than a failed allocation. `vm.max_map_count` is 262144 too, as images such as Elasticsearch ask.

Known issues: a signal handler's edit to `uc_sigmask` is still ignored under FEX, which by reading the code can make musl's `pthread_cancel` of a busy thread spin (not reproduced). A handler that reads
EFLAGS during `rep cmps` sees wrong PF and AF.
The AAAA fix of 0.4.2 has still not run on the network that first showed the failure.

The guest changes in this release: it carries the new emulator, so updating downloads it once.
