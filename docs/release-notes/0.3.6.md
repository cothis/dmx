## Changes since 0.3.5

This release makes sure disk space the VM frees goes back to the Mac.

- **The data disk is trimmed when the VM goes idle.** Deleting files already gives their space
  back at once, but blocks freed without that never were. That happens after an unclean stop,
  when the journal is replayed or the disk is repaired, or when a discard is lost because the VM
  was killed. On one Mac, `data.img` held 5.9 GB on the host for 260 MB of data. The idle sweep now
  trims the disk once per idle spell and the daemon log says what came back. The trim takes 10 ms
  on a 64 GB disk after boot, and 0.24 s right after 3 GB was deleted. An existing `data.img`
  shrinks at the first idle moment once the VM runs the new guest (after its next start).
- **daemontest checks it.** It frees 256 MB without discard and waits for the sweep. With 0.3.5's
  guest the file stays at 266 MB; with this one it goes back to 10 MB.

Qualification passed 59 unit tests, 23 VM selftests, 58 daemon checks, 33 MCP checks, 53 x86
checks, 69 Docker checks, 44 sandbox checks, all 24 digest-pinned image cases across arm64,
amd64 and 386, and the 100-run Java gate. Idle VM footprint and memory return are unchanged
(97 MiB; about 1 GiB returned in 217–322 ms). The guest's emulator is still `fex-2610-dmx11`; only the guest agent changed.
