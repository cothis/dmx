## R1 — P2: failed read lease can permanently shift RPC replies

**Introduced by v0.3.11.** `Sources/DMXCore/Agent.swift:162-170` duplicates the descriptor
once per frame. `reply()` at lines 177-183 obtains separate write/read leases. If the write
succeeds and the following duplicate fails with `EMFILE`, the request has been sent but
the response is not read. `AgentClient.call()` at lines 372-380 propagates this error
without replacing the connection; replacement is reserved for a timeout. `readReply()`
at lines 306-324 does not validate the response ID.

The next RPC can consume the previous RPC's response. Different methods can get decoding
errors; repeated methods can silently receive stale data. Immediate replies need not time
out, so the existing timeout recovery does not restore alignment.

The parent linked the actual debug DMXCore implementation into an isolated executable
and used a synthetic peer answering request IDs in order. A child-process-only Darwin
interposer returned `EMFILE` for the second client `F_DUPFD_CLOEXEC` call. This is fault
injection at the syscall boundary, **not a measurement of real FD exhaustion frequency**
and not an injection into the signed published binary.

- Control: `first` returned `first`; `second` returned `second`; exit 0.
- Injected: `first` threw `agent_disconnected: Too many open files`; the actual
  `AgentClient.call("second", ...)` returned owner `first`; property failure, exit 1.
- The first attempted interposer harness crashed before a valid injected experiment; it
  was corrected before the cited control/injected runs. That harness crash is not attributed
  to dmx ([initial harness log](../formal/frame-connection-lifetime/evidence/opus55/interposer-harness-first-attempt.log)).

Evidence: [control](../formal/frame-connection-lifetime/evidence/opus55/emfile-control-agent.log),
[injected failure](../formal/frame-connection-lifetime/evidence/opus55/emfile-injected-agent.log).

Follow-up designs include retaining one lease for the complete request/reply, or retiring
and replacing a connection after a failure that can lose reply alignment. Do not blindly
retry the request: the guest may already have applied its side effect. Also consider
checking response IDs. The exact recovery design is follow-up work.

## R2 — P2: the fixed model cannot detect a removed close guard

**Verification defect, not evidence that the correct current guard fails.** In
`formal/frame-connection-lifetime/tla/Spec.tla:25` and `:33`, both observation flags are
conditioned directly on `~LeaseFD`. With `LeaseFD = TRUE`, they stay false regardless of
whether `Acquire` rejects a closed connection. The fixed model assumes the lease targets
the original socket rather than deriving the target from an acquisition and binding state.

The parent copied the model, kept `Properties.tla` unchanged and replaced the `Acquire`
closed-check conditional at line 24 with unconditional `"active"`. TLC still returned 0:
**254 generated / 108 distinct states, depth 13**, with both protocol invariants passing.
The original 134-state run is a historical model result, but the claim that the original
fix-toggle mutation sufficiently validated regression sensitivity was too strong.

Evidence: [close guard removed, model still passes](../formal/frame-connection-lifetime/evidence/opus55/model-without-close-guard.log).

Follow-up: model per-operation descriptor bindings/ownership and derive the observations
from accepted operations and their actual targets. Independently mutate the close guard,
lease acquisition, and lease lifetime. Preserve the frozen protocol properties.

## R3 — P3: the socket tests do not independently protect close's wakeup

`Tests/DMXCoreTests/FrameConnectionTests.swift:101` explicitly shuts down the peer. That
can wake a reader even if the production shutdown in `Agent.swift:156` is missing.

The parent built an isolated synthetic Swift package from the unchanged Core sources,
except for removing that one shutdown line. It ran the original three socket tests:
**3/3 still passed**. This proves a unit regression gap, not that the current shutdown
implementation is broken. No claim is made that every integration test would also pass
this mutation. The original correspondence note overstated the unit evidence for wakeup.

Evidence: [shutdown removed, tests still pass](../formal/frame-connection-lifetime/evidence/opus55/no-shutdown-tests.log).

Follow-up: start a blocked read (and a blocked write), invoke close/abort alone and require
completion before allowing peer-side teardown. Keep header/body socket identity separate
from the wakeup assertion.

## R4 — P2, parent finding: FD reuse tests can close another test's file

**Test-only defect.** `FrameConnectionTests.swift:27-35` and `:96-97` release a descriptor
number and then force `dup2` into it. `@Suite(.serialized)` at line 6 serializes only that
suite, while the other suites can open files concurrently.

Allowed schedule: close the fixture FD -> another test opens a file at that number ->
the fixture's `dup2` implicitly closes the other test's descriptor and replaces it with a
socket. The parent forced that syscall order in an isolated executable using the actual
FrameConnection close; the unrelated file descriptor became a socket. This establishes
the mechanism, not a measured whole-suite flake rate. It was found by the parent,
**not attributed to Opus**.

Evidence: [forced unrelated-open interleaving](../formal/frame-connection-lifetime/evidence/opus55/test-fd-reuse.log).

Follow-up: isolate destructive descriptor-table tests in their own process rather than
relying only on per-suite serialization.

## Scope and next work

The original wrong-socket framed-I/O defect is still considered fixed. Read-only review
did not find a shutdown-on-close regression or a defect in the ordinary guest receipt
update path. This review is not a proof of the whole program, a production incidence
measurement, or a replacement for the recorded release qualification.

Prioritize R1's reply correlation and recovery, then strengthen the model and test
mutations (R2/R3) and isolate the tests (R4). Product fixes and any subsequent release are
follow-up work. [Reproduction sources and commands](../formal/frame-connection-lifetime/repro/opus55/README.md)
are retained; the reviewed product source and published release remain at their recorded versions.
