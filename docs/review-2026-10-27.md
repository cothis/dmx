# Pre-announcement review, 2026-10-27

The review started from clean `main` at `5347942`, fast-forward synchronized with `origin/main`.
The published release is v0.3.3. The fixes below are on main and require a new patch release before
announcing them as available to users; no tag, release or community post was created by this review.

## Findings fixed

| Priority | Finding and trigger | Change and evidence |
|---|---|---|
| P1 | A guest FUSE RELEASE could close a descriptor after READ/WRITE/GETATTR/SETATTR/FSYNC looked it up. Another host open could reuse that number before the request used it. RELEASEDIR similarly closed a `DIR*` still held by READDIR. | Duplicate the descriptor under the handle lock and close the duplicate at request completion; directory streams close when the last reader releases the object. A regression holds an I/O descriptor across guest release and a new host open, verifies the original file is written and the outside file is unchanged. A concurrent directory read/release test exercises stream lifetime. This is a code-path finding with focused regression coverage, not a demonstrated end-to-end guest escape. |
| P2 | A read-only share accepted OPEN with `FUSE_OPEN_KILL_SUIDGID` and cleared the host file's set-ID mode bits. | Refuse that mutating open with EROFS. Before the fix the test failed both the error check and preservation of mode 06755; after it both pass. |
| P2 | Virtqueue ring addresses near UInt64.max overflowed during offset arithmetic before the guest-RAM bounds check, terminating the host process. | Validate the complete descriptor and ring ranges before arithmetic, queue sizes and available indices before use, and completion lengths before UInt32 conversion. The pre-fix test exited with signal 5; boundary, malformed and ordinary completion cases now pass. Rings without EVENT_IDX need no unused trailing event field. |
| P2 | Sandbox allowlist entries `/`, `//` or an empty string produced no split components and indexed an empty array; a trailing slash was also silently accepted. | Keep and reject empty components. The pre-fix test exited with signal 5 (`Index out of range`); valid IPv4/CIDR entries and invalid-input errors are tested, including requests over MCP. |
| P2 | Sizes from 2^63 through UInt64.max passed `parseSize`, then trapped when VM memory, disk offsets or Docker limits converted them to signed integers. | Refuse sizes outside the signed host range before saving config or creating a sandbox. Tests cover raw bytes, scaled sizes, memory, disk size and sandbox limits. |
| P2 | An MCP sandbox TTL such as `1e100` was converted directly from Double to Int, terminating the MCP server. | Use the checked integer argument reader. Both signs of the out-of-range value return tool errors over stdio; subsequent requests still work. Docker JSON integer conversion also rejects nonrepresentable/fractional doubles. |
| P3 | README still called IPv6 missing, download verification wording omitted the updater's trust model, help/release docs said the updater quit idle daemons, and HANDOFF mixed several released versions with an obsolete “unreleased” list. | Correct the feature and evidence boundaries, update handover text and release checks, and replace the stale handoff with the current state. |

## Published installation and repository checks

- Downloaded v0.3.3's installer, binary archive, release notes and third-party inventory from GitHub;
  all four match SHA256SUMS. The published installer matches the repository template with the
  version and binary digest substituted. It installs 0.3.3 into an isolated prefix.
- The downloaded binary passes strict codesign verification against Apple's anchor and team
  V4YA23448U, and `codesign --verify --strict --check-notarization`. Plain `spctl --assess` reports
  “the code is valid but does not seem to be an app” for this standalone CLI, so that result alone
  is not treated as a notarization failure or an application-launch acceptance test.
- A fresh DMX_HOME downloads and verifies the v0.3.3 guest and passes selftest (97 MiB).
  All four boot-file hashes match the locally built guest used in the suites. A forced
  same-version update in the isolated prefix reports the expected Developer ID and replaces
  the binary successfully. No existing user VM, Docker context,
  launchd installation or data disk is replaced by this check.
- The release has 14 uploaded assets, including the 496,179,200-byte source bundle. Its packaging
  recipe includes the kernel/TSO, QEMU and FEX sources and patches. The large source bundle was not
  re-downloaded or rebuilt during this review.
- Python and shell syntax checks pass. Relative Markdown file links are checked. Tracked artifact
  and credential-pattern scans found no generated caches or credentials; the private-key marker
  in `DockerTests.swift` is the deliberate invalid `CCCC` PEM parsing fixture.

## Remaining acceptance boundaries

- These fixes still need the maintainer's version/release decision, signing, notarization and
  published-artifact verification. The currently published v0.3.3 does not contain them.
- External IPv6 needs a host network with IPv6 routing. Corporate TLS-inspection proxy/VPN
  acceptance needs that environment; local proxy, CA and loopback tests do not establish it.
- This pass does not replace an independent security audit, exhaustive hostile-device fuzzing,
  another physical Mac or a long-duration soak. No new comparison against other engines was run;
  README's comparison remains the dated 0.3.0 benchmark.
- The already documented product limits remain: one shared guest kernel, DNS lookups under a
  sandbox allowlist, no arbitrary host Unix-socket bridge or shared-file ACL/DAX support, and
  386 support through FEX only. Phase 8's own runtime is still unstarted.
